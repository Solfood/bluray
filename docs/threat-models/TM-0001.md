# Threat Model — Full-app refactor (static SPA → self-hosted RRv7 + SQLite)

- Work item / Decision ID: BLU-ARCH-0002 / DEC-0002
- Date: 2026-07-06
- Risk class: medium

## Assets

- **github_token** — server env var, used only for nightly backup pushes to the repo.
- **tmdb_api_key / anthropic_api_key** — server env vars; Anthropic key has real spend attached.
- **Movie collection data** — SQLite DB on `/data` volume (canonical) + `movies.json` exports. Not PII, but the project's core asset.
- **Service availability** — low criticality (personal LAN app).

## Trust Boundaries

1. **LAN client → Node server.** The big shift: previously the browser held all secrets; now the server does. There is no auth, so *every device on the home network* sits inside the user trust zone.
2. **Server → third-party APIs** (TMDB, Anthropic, GitHub). Responses are untrusted input that gets parsed, stored, and rendered.
3. **Server → SQLite file / `/data` volume** (container → host mount).
4. **Container → host** (Docker isolation).
5. **Migration script → movies.json** (one-time, local file).

## Entry Points

- HTTP loaders/actions on the LAN: movie add/edit/delete, search query, barcode string, cover-photo image upload, retry-enrichment.
- Third-party API responses (TMDB JSON, Anthropic completions) parsed server-side.
- Env vars at container start.
- `movies.json` file consumed by the one-time import script.

## Abuse Cases

- **External attacker (no LAN access):** out of scope *if* the LAN-only assumption holds. The real threat is the assumption silently breaking (router port-forward, UPnP, container binding 0.0.0.0 on a host that's reachable).
- **Malicious/compromised LAN device** (guest wifi, IoT): can read/modify/delete the collection and spam the identify endpoint to burn Anthropic credits. Cannot read secrets (server-side, never sent to clients).
- **Compromised third-party response:** crafted TMDB/Anthropic output could inject hostile strings into the DB and UI, or oversized payloads.
- **Insider:** N/A — single-occupant trust zone.

## Threats Identified

**S — Spoofing:** No auth means any LAN device *is* the user. Accepted by explicit design decision (single user, LAN only). Mitigation is network posture, not app auth.

**T — Tampering:** Same LAN exposure applies to writes. GitHub backup history provides tamper-evidence (every nightly export is a diffable commit). Backup pushes must be non-force.

**R — Repudiation:** Genuinely low value for a single-user app; git backup history doubles as a change record. No further controls.

**I — Information Disclosure:** Strict improvement over status quo (secrets leave browser localStorage and the Gist vault). Remaining vectors: secrets visible via `docker inspect`/compose file on the host; keys accidentally logged; DB file readable on host.

**D — Denial of Service:** Only the cost-bearing endpoint matters: identify (Anthropic). App availability itself is low-stakes.

**E — Elevation of Privilege:** GitHub token is the escalation vector if the server is compromised. Container hardening bounds the blast radius.

| Threat | STRIDE | Severity | Mitigation | Residual Risk |
|--------|--------|----------|------------|---------------|
| LAN-only assumption silently breaks (port-forward, 0.0.0.0 exposure) | S/T/I | high | Bind container port to LAN interface only; no port-forwarding; document check in release-readiness; secrets never sent to client | Router misconfig outside app control — periodic manual check |
| Any LAN device can write/delete collection (no auth) | S/T | medium | **Risk-accepted by owner** (DEC-0002: single user, LAN only). Nightly git backups make damage recoverable and evident | Malicious LAN device between backups loses ≤1 day of changes |
| LAN device spams identify endpoint, burns Anthropic credits | D | medium | Image size/type caps before API call; monthly usage cap enforced from `scan_usage` table (hard stop, not just counter) | Cap-sized spend (~dollars) before cap hits |
| Hostile TMDB/Anthropic response content stored + rendered (stored XSS) | T/I | medium | React default escaping; no `dangerouslySetInnerHTML` for API-sourced fields; shape-validate API responses before insert; length caps | Low — requires third-party compromise and an escaping gap |
| Server compromise exposes github_token | E/I | medium | Fine-grained PAT: this repo only, `contents:write` only, expiry set; non-root container, no extra capabilities | Repo content tampering until token rotated; bounded by scope |
| Secrets leak via host (compose file, docker inspect, logs) | I | medium | Env via `.env` file mode 600, gitignored; never log key material; error messages redact keys | Host root can always read — acceptable, it's the owner's box |
| Migration loses/corrupts collection data | T | high | Lossless import→export round-trip test against real movies.json; git copy stays canonical until cutover; parallel run before cutover | Near zero — rollback is a pointer flip while git copy is current |
| Backup push fails silently, eroding tamper-evidence + recovery | R/T | medium | "Last backup: N days ago" UI indicator; failures logged | Owner ignores indicator |
