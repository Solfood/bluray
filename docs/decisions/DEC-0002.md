# DEC-0002: Refactor static SPA to self-hosted React Router v7 full-stack app

- Date: 2026-07-06
- Status: accepted
- Owner: Solfood
- Marker: BLU-ARCH-0002
- Supersedes: N/A
- Threat model: [TM-0001](../threat-models/TM-0001.md) (Gate 2 — complete)

## Context

The app is a static React SPA where git is the database: `movies.json` lives
in the repo, the browser writes to it via Octokit using a personal GitHub
token stored in localStorage, enrichment runs via a GitHub Actions Python
scraper, and API keys sync across devices through a private Gist. The site
recently moved off GitHub Pages to a self-hosted Docker-capable home server
(`bluray.local`), which makes a real backend possible for the first time.

## Intake

- Objective: Replace the static SPA + git-as-database architecture with one
  self-hosted full-stack app owning a real database, with all secrets
  server-side and enrichment/identify running on the server.
- In scope: React Router v7 (framework mode) rewrite; SQLite data store;
  server services for TMDB lookup, Claude cover identification, enrichment,
  and GitHub backup export; one-time movies.json → SQLite migration; Docker
  packaging; retirement of `web/`, Python scrapers, and the enrichment
  GitHub Actions workflow.
- Out of scope: local poster/image hosting (deferred); auth/multi-user;
  remote access; changes to the sibling suite repos.
- Risk class: medium
- Critical assets touched: movies_json (migrated to SQLite, becomes export),
  github_token (moves from browser localStorage to server env, backup-only
  scope), tmdb_api_key (moves to server env).
- Dependencies: React Router v7, better-sqlite3, Vitest, Docker on the home
  server.
- Expected evidence: lossless movies.json import→export round-trip test;
  service unit tests passing; parallel-run period before cutover; first
  successful automated backup push before old code deletion.

## Options Considered

1. **Node API + SQLite behind the existing Vite SPA** — smallest change,
   keeps frontend untouched, but retains the SPA/API split and two build
   surfaces.
2. **Python FastAPI backend + existing SPA** — reuses `details_scraper.py`
   directly, but locks in two languages and the browser TMDB/Anthropic logic
   must be ported to Python anyway.
3. **React Router v7 full-stack rewrite** (chosen) — one app, one process,
   one container; loaders/actions replace the client data layer; Vite,
   React, Tailwind, and existing components carry over.

## Decision

Rebuild as a React Router v7 framework-mode app with SQLite, deployed as a
single Docker container with a `/data` volume. Database is the source of
truth; a nightly job exports byte-compatible `movies.json` and pushes it to
GitHub as a versioned backup. Full design: `docs/superpowers/specs/2026-07-06-full-app-refactor-design.md`.

## Why

Owner explicitly chose the full-stack rewrite over the incremental options.
React Router v7 minimizes the rewrite cost within that choice: the component
layer ports nearly as-is, while the fragile parts (token in localStorage,
Gist vault, git-as-database, Actions round-trip enrichment) are deleted
rather than ported. Single-user LAN scale makes SQLite and an in-process job
model the right size — no queue, no DB container.

## Risks & Mitigations

| Risk | Mitigation |
|------|-----------|
| Data loss during movies.json → SQLite migration | Lossless round-trip integration test against the real file; old file remains canonical until cutover |
| New app regresses features silently | Parallel run on a separate port for several days before cutover |
| Backup pipeline fails silently after cutover | "Last backup" indicator in UI; old code deleted only after first successful automated push |
| GitHub token on server compromised | Fine-grained PAT: this repo only, contents:write, expiry set; non-root container (TM-0001) |
| Enrichment port (Python → TS) drops fields | Enrichment mapping unit tests compare output shape against existing enriched records |
| LAN-only assumption silently breaks | Bind to LAN interface only, no port-forward; check added to release-readiness (TM-0001) |
| LAN device burns Anthropic credits via identify endpoint | Image size caps + hard monthly usage cap from scan_usage table (TM-0001) |
| No-auth on LAN — any device can write | **Risk-accepted by owner**; nightly git backups bound loss to ≤1 day (TM-0001) |

## Rollback Plan

Cutover is a web-server pointer change; rollback is pointing it back to the
static site, which remains deployed and whose `movies.json` is current up to
the cutover moment. Old `web/` code is deleted only after the first
successful automated backup push proves the export path.
